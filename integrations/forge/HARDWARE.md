# Hardware kit analysis companions

Sixteen companions cover the kit lessons for image and object recognition, keyword spotting, motion classification, Raspberry Pi LLM/VLM analysis, and shared audio feature engineering. Platform navigation is excluded and setup remains local; the coverage catalog gives each source page a disposition. No hosted notebook claims to flash, deploy to, or measure a device.

Each companion links its canonical lesson and accepts one compact imported file (at most 2 MiB). Nothing runs until **Analyze imported evidence**, and publishing the resulting preview is a separate action. No device data is prefilled. Without real imports, the hosted notebook's validation covers its interface and parsers only.

- **Dataset preparation:** import CSV with `sample_id,label,split`, where split is `train`, `validation` or `test`. The analyzer rejects repeated sample identities and empty train/test sets, reports counts by split and hashed class label, and keeps raw identities, class names and examples local. This checks manifest consistency, not image/audio content duplicates or label correctness.
- **Model analysis:** import JSON with a `model_sha256` and `parameter_tensors`, each containing `shape` and `dtype`. Optional `flash_budget_bytes` records the actual device constraint. Parameter counts and storage estimates are supplied-case calculations; they exclude activation RAM, allocator arena, format overhead and runtime memory. Keep the model artifact itself local and use its digest for lineage.
- **Device measurements:** import JSON with `board`, `capture_method`, `model_sha256`, `firmware_sha256`, and a `measurements` list. Supported fields are `latency_ms`, `energy_mj`, and `power_mw`. Optional `conditions` records ambient temperature, clock, batch size, warmup count and power scope. The report retains units and sample counts, mean, median, minimum and maximum. It labels these imported measured experiments and does not attest authenticity or independence.

Use the canonical lesson's data collection, preprocessing, model export and device measurement procedure. Keep sampling rate, windowing, sensor placement, quantization and physical constraints in the original local records; a notebook summary cannot replace them. Report failed validation explicitly and do not substitute synthetic readings for device measurements. Unit tests use labeled test fixtures solely to verify calculations.
