# Optional SFT and RLVR companions

These companions prepare a reproducible training handoff for the same synthetic task used by [hosted evaluation](HOSTED.md). Preparation is local and creates no job. The [research contract](RESEARCH_CONTRACT.md) freezes the training/evaluation split, checker and comparison rules.

The SFT companion writes 24 synthetic demonstrations to `trajectories.jsonl` with a metadata file containing both split digests and the source commit. These are supplied labels, not model traces. Upload the files as a private dataset artifact only after explicit review; use its immutable `wandb-artifact:///entity/project/name:vN` reference in an SFT request. Preserve the artifact identity in the request receipt. Do not upload the evaluation rows as training data.

For RLVR, execute `run_evaluation(..., split="train")` twice with distinct, separately reserved attempts and the same explicitly selected policy. `rlvr_groups` builds real trajectory groups from the preserved completion choices and computes exact tool-selection rewards. It reports unavailable groups and uniform rewards. A perfect, uniform smoke provides no relative reward signal: do not claim that a no-op RL step improves a model. Keep all rollout action IDs and hashes alongside the job request.

`submit_once` implements the documented SFT and RL job endpoints with no automatic POST retry, a shared budget reservation and a durable request/job receipt. It requires a `verify_service_limit(endpoint, project, request)` adapter that reads an enforceable service policy and returns a maximum cost, policy reference, exact request digest and matching project. A handwritten dollar allowance, small batch, local timeout or estimated runtime does not satisfy that contract. No limit adapter is supplied because the public API currently documents no job cost/runtime cap or cancellation endpoint. Thus live submission is blocked by default, before credentials, uploads or jobs. This is an explicit unvalidated capability, not a successful training result.

Once the service offers a verifiable bound, supply the adapter, validate the selected base model against `GET /preview/base-models`, register a model in the verified private project, and submit exactly one prepared request. SFT accepts `model_id`, `training_data_url` and `config`; RL accepts `model_id`, real `trajectory_groups` and supported `experimental_config`. Do not invent `max_cost` or `max_duration` fields. See the current [API reference](https://docs.coreweave.com/products/post-training/serverless-training/api-reference) and [usage limits](https://docs.coreweave.com/products/post-training/serverless-training/usage-limits).

`monitor_job` records status snapshots and recognizes only completed, failed or cancelled jobs as terminated. Its polling deadline does not stop a remote job or release its cost reservation. An uncertain submission must be reconciled against the service before a new attempt. Keep checkpoint artifacts; do not automatically delete or promote them.

For before/after evaluation, explicitly select the resulting served checkpoint model from the available service catalog and rerun the held-out split with unchanged settings. `paired_comparison` requires actual training-job/checkpoint lineage and shows gained, lost, shared-correct, shared-incorrect and unavailable task IDs. No before/after quality claim is possible until an actual bounded job, terminal status, checkpoint and both evaluation arms have been verified.
